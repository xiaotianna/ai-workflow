# 简历表达

下面的内容是表达模板，不应直接当作个人经历照抄。请只保留你真实负责、能够展示代码并经得住追问的
部分，再补充可验证的数据。

## 一句话介绍

设计并实现可视化 AI 工作流平台，覆盖节点编排、版本发布、可靠调度、Go 节点执行器与第三方插件体系，
支持模型、知识库、HTTP、Code 和子工作流等能力组合。

## 简历要点模板

- 将工作流领域模型、纯 Runtime 状态机、NestJS 运行宿主与 Go 单节点执行器解耦，降低调度逻辑对
  数据库和消息队列的耦合，并支持持久化恢复。
- 基于 PostgreSQL Outbox/Inbox、RabbitMQ Publisher Confirm、运行 revision 与租约机制，处理消息
  丢失、重复投递和过期任务，保证工作流状态只推进一次。
- 设计版本化 JSON Schema 协议连接 TypeScript 与 Go，统一 Command/Result 校验并保留协议兼容边界。
- 设计可序列化插件 SDK 与 CLI，支持 Schema/Form DSL、自定义 React UI、Executor Artifact、完整性
  摘要、确定性打包及 Marketplace 发布。
- 基于 React 19、React Flow 和 Schema 驱动表单构建工作流编辑器，统一节点配置、变量引用、运行状态和
  插件节点渲染。

## 把数据补完整

可量化结果必须来自真实压测或线上数据，例如：

- 单个工作流支持的节点规模与画布渲染耗时；
- Runtime 每秒可推进的状态转换数量；
- RabbitMQ 消息重投下的重复结果拦截率；
- 插件构建时间、产物大小或冷加载耗时；
- 前后端类型/Schema 复用后减少的重复代码量。

不要使用“性能提升 50%”“零故障”等没有基准和测量方法的数据。
