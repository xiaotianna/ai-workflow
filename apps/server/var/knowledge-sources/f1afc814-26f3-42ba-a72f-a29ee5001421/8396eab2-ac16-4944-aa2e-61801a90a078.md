## 组件文档编写规范（以 Sidebar 页面为基准）

### 适用范围

- 基础组件文档：`docs/guide/components/**`
- 业务组件文档：`docs/business/**`

### 页面结构

- 基础组件页面默认结构：
  1. `# 组件名`
  2. `## 使用说明`（2-4条，说明适用场景/能力边界）
  3. 一个或多个 `## xxx 使用示例`
- 业务组件页面默认结构：
  1. frontmatter（建议 `pageType: doc-wide`、`outline: false`）
  2. `# 组件名`
  3. `## 使用说明`（明确“基于哪些基础组件封装”）
  4. `## 使用示例`（完整组合示例）

### 示例代码规范

- 演示代码统一使用 `tsx preview` 代码块。
- import 路径必须与项目真实路径一致，优先 `@/components/blocks/*`。
- 示例必须可直接渲染，不写伪代码。
- 示例代码为保证页面可渲染，默认直接渲染目标组件，非必要不要额外包裹 `div`。
- 仅在确有需要时（如加间距、边框、定高、overflow 隔离）再添加容器；添加容器时需补充 `h-full`，并只保留必要样式。
- 同一个组件存在多个示例时，示例小节标题必须清晰区分变体与能力点，推荐格式：`## {组件名} {变体/编号} 使用示例（{关键能力}）`，例如：`## Sidebar 17 使用示例（含 Tab 切换）`。
- 每个示例必须明确标注“使用了哪个组件”（写在小节标题或示例前说明中），例如：`使用组件：Sidebar 17`。
- 对于包含 `Sidebar` / `Sheet` / `fixed` 布局特征的组件，示例必须放入容器并加隔离样式，避免溢出文档布局：
  - 容器：`relative` + 固定高度 + `overflow-hidden` + `rounded-xl border`
  - 覆盖：`[data-slot="sidebar-wrapper"]` 设 `height: 100%`
  - 覆盖：`[data-slot="sidebar-container"]` 只设 `position: absolute; top: 0; bottom: 0; height: 100%`
  - 禁止在文档覆盖里使用 `inset: 0`，否则会破坏侧栏折叠位移逻辑。
- 对于 `Select`、`DropdownMenu`、`Menubar`、`ContextMenu` 等带“分组语义”的组件，子项必须放在对应的 `*Group` 容器内（如 `SelectGroup`、`DropdownMenuGroup`）；不要直接平铺 `*Item`，以保证结构语义、键盘交互与样式行为一致。

### 内容要求

- 基础组件页：至少说明“什么时候使用这个组件”。
- 业务组件页：至少说明“由哪些基础组件组合而来”和“关键交互”。
- 同一能力若有多个变体（如 standard/outline），必须分别展示，再提供混合示例（放业务组件页）。

### 目录与元数据

- 新增页面时必须同步更新对应 `_meta.json`。
- `docs/guide/components/components` 放基础组件示例。
- `docs/guide/components/blocks` 放基础区块示例。
- `docs/business` 放业务组合示例。
